# Numerical correctness

The reference is [TRL v0.24.0 GRPOTrainer](https://github.com/huggingface/trl/blob/v0.24.0/trl/trainer/grpo_trainer.py),
source SHA-256 `bb6905182acf2ec426f1dc9ffc37e5210d58ee47d2764f7cf12dbb90a4a28954`.
Installed source bytes are fingerprinted during fixture capture.
See the [versioned official documentation](https://huggingface.co/docs/trl/v0.24.0/grpo_trainer).

`fixtures/trl/{group,none,batch}.json` are captured from **actual calls to
GRPOTrainer._generate_and_score_completions**, using `super()`'s returned
advantages during actual CPU training. The capture script does not call PTM's
kernel to generate expected outputs. It records source version, dtype, seeds,
input rewards, grouping, outputs and evidence that model parameters changed.

```bash
.venv/bin/python scripts/capture_golden.py
.venv/bin/pytest tests/test_numerical.py tests/test_trl_parity.py tests/test_trl_live.py -v
```

The PTM kernel uses float64; reference training uses Torch float32. Parity uses
`atol=2e-6, rtol=1e-5`. An independent scalar reference and Hypothesis properties
provide a second check. Group scaling uses **sample std (`ddof=1`)** and
`A=(r-group_mean)/(std+1e-4)`; unscaled mode centers only. Batch mode centers by
group and scales by the entire declared reward batch. It requires explicit
`reward_batch_scope=full_snapshot`, complete capture and no group subset.

Singleton groups are rejected under sample-std group scaling. Missing or invalid
rewards are rejected before arithmetic, even though the original TRL aggregator
can skip missing reward components with `nansum`; only the supported complete
combined scalar reward path is compared. NaN, infinity and arithmetic overflow
never become plausible-looking numerical results. Population variance is used
only as a descriptive group statistic; it is labeled separately from the
sample std used in the algorithm.

Imported runs must declare recipe_id explicitly. Native TRL version conflicts
disable advantages consistently in doctor, summary, Inspector and reward diff.
Batch replay also requires matching known captured/expected group counts, no
drops or capture errors, and full run-level and group-level sampling probability.
An `affected` completion includes component-only and advantage-only changes.
Only exact 0/1 grades from one named verifier can form binary mismatch flags;
other finite grades retain their numeric score without an inferred pass threshold.

The synthetic demo reports `verifier_accuracy` on its saved completion cohort.
It is labeled saved-sample verifier accuracy and is not an independent held-out
split. Real `heldout_accuracy` series can be imported with their own declared
source. Duplicate name/step metric entries and source changes within a series
are rejected instead of silently mixing evaluator results.

Ranks are competition ranks (1,1,3). Strict pairwise ordering reversals count;
ties alone are not reversals. Sign flips require strictly opposite nonzero signs.
Adding a constant preserves centered advantages. Positive scaling is **not
exactly invariant** when epsilon is nonzero; the property test checks the actual
denominator correction.

L2 capture records the native forward's current logprobs and the actual inputs
used for the denominator/reference, with separate identities. When native TRL
uses `current.detach()` for its absent old tensor, the adapter records that exact
branch; it does not call the same numbers behavior-policy sampling logprobs.
Behavior logprobs remain missing when unavailable.

`tests/test_signals.py` independently checks token ratios, sampled KL, clipped
surrogates, masks, four normalizations and complete rank/microbatch grids.
`tests/test_deep_live.py` runs actual CPU trainer steps for GRPO, BNPO, DAPO and
Dr.GRPO, plus AdamW and SGD. Native objective scalars and callback-captured native
post-update weights are the references, never outputs generated by PTM itself.
The frozen actual L2 data lives in `fixtures/l2/native*.json`; the 5000-token
stress fixture is separately synthetic. A two-process CPU test checks actual
native global advantages across rank spools.

For a full uniformly sized rank/microbatch grid, let L_i be each completion's
masked token-loss sum and n_i its effective length. GRPO averages
L_i/max(n_i,1). Dr.GRPO divides sum(L_i) by B*max_completion_length. BNPO averages
cell-wise masked sums divided by effective cell tokens. DAPO divides the global
sum by the declared global effective token count. Missing cells, policy mismatch,
partial capture, unsupported modifiers and inconsistent denominators fail closed.
An entirely masked sequence has zero contribution; an all-masked objective is
rejected. Captured sequence advantage is broadcast across tokens, not presented
as an independently learned token advantage. Sampled KL is not full-vocabulary KL.

Objective replay is float64 NumPy on fixed tensors. Bounded actual replay restores
float32 model/optimizer/RNG state and executes forward/backward/clipping and one
native optimizer step. Tests use atol=2e-6 and rtol=1e-5 for objective parity and
max absolute native weight error ≤2e-6 for original updates. A reward-patched
branch executes from the same before-state and has no original native parity
claim. The current actual DAPO fixture measured loss discrepancy 1.86e-9 and
maximum native weight discrepancy 5.53e-11. These are fixture measurements,
not universal error bounds. Long-term model quality and GPU determinism remain
unverified. Reports can recompute included L2 objective evidence offline; ordinary
report bundles deliberately exclude weights, optimizer states and private files.
